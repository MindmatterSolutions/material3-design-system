# design-sync notes — Material Web (themed)

The synced package is `react/` (`@mindmatter/material-web-react`): @lit/react
wrappers around Google's @material/web, generated by `react/tools/generate.mjs`
from @material/web's own types. The repo root `.design-sync/` is the config home;
run the converter from the repo root.

## Build
- `cd react && npm install && npm run build` → `react/dist/{index.js,index.d.ts,styles.css,fonts/}`.
- Converter: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules react/node_modules --entry react/dist/index.js --out ./ds-bundle`.
- `react/dist/styles.css` is the whole theme flattened (fonts, tokens/base, m3-expressive, components/m3-system.css, components/theme-bridge.css) because cfg.cssEntry is copied verbatim, not import-followed, and fonts outside the package dir are skipped. Fonts are copied into react/dist/fonts/.
- labs/gb imports CSS as module scripts (`with { type: 'css' }`); both esbuild builds (components/ and react/) use a plugin that turns them into constructed CSSStyleSheets.
- Playwright: the cached chromium is build 1234 → playwright@1.62.0 in .ds-sync.

## Theme / previews
- The theme is dark only. cfg.provider = `ThemeRoot` (react/src/theme-root.tsx) paints the surface; the bridge also paints `html, html body` so designs without ThemeRoot aren't light-on-white.
- Icons: the synced package ships the FULL Material Symbols fonts (Rounded default, Outlined, Sharp; 4,299 names) from fonts/material-symbols-full/ via components/icons-full.css — ~12.9 MB of woff2 in the upload. react/tools/build.mjs drops the bridge's 67-icon subset face so only the full fonts ship. The repo's own pages still use the subset (fonts/material-symbols/).

## Known render warns
- `[RENDER] root empty` on one random card per validate run was seen during the first sync (2026-10-05), after the full icon fonts (~12 MB) started shipping: the card's screenshot had content, so the checker read the root before React mounted. It did not reproduce on 2026-10-08 (two consecutive full render checks, 65/65 clean, converter re-staged from Claude Code 2.1.293). If it returns, re-run once; a card flagged on two consecutive runs is a real failure.
- `[TOKENS_MISSING] --md-icon-*`: registered with @property initial values in components/m3-system.css; not a gap.
- `[RENDER_THIN] Slider` floor card: sliders paint no text; resolved by an authored preview.

## Preview recipes (folded from the first sync's preview waves)
- Menus held open statically: `ExpressiveMenu` → remove its `popover` attribute in a `useEffect` (it sets `popover="auto"` only on connect) and give the host `display:'block'` + a width; `ExpressiveDivider` inside it needs `className="divider"`. Stable `Menu` → `anchor="<button id>" positioning="absolute" open quick stayOpenOnOutsideClick stayOpenOnFocusout defaultFocus="none"` inside a `position:relative` host with min-height; anchor ids unique per file.
- `NavigationBar` must sit in a `position:relative` fixed-height flex column (phone frame) or it pins to the viewport.
- `Dialog` previews render with `open quick`; cfg.overrides.Dialog = single card 720x520 so the two modals don't stack in one card document. The first action shows a focus ring (dialog focuses it on open) — inherent.
- `ThemeRoot` previews use the default accent only: `accent` sets `<html data-accent>` (one accent per page). Captures (`?story=`) isolate cells, so a leak only shows on the real multi-cell card page.
- Never name a story export `Error` (shadows the global).
- `ElevatedCard`/`ExpressiveCard` have no padding: wrap content in a padded div. `LinearProgress` needs `width:100%`.
- Interaction-only states are not previewed: slider value bubbles (`labeled`), split-button menu, hover/press, `fourColor` (only differs over time).
- Select option list held open statically: ref on the select, `showPicker()` in a useEffect (~50 ms timeout), `quick menuPositioning="absolute"`, explicit `style={{width:320}}`, host `position:relative; minHeight:380`. The selected option shows a focus outline (showPicker focuses it) — inherent.
- SubMenu held open: parent `Menu` needs `hasOverflow`; nested `<Menu slot="menu">` gets `anchor="<slot=item MenuItem id>" anchorCorner="start-end" menuCorner="start-start" hasOverflow` + the static-open Menu props; the item gets `selected`. cfg.overrides MenuItem/SubMenu/SelectOption = column (open menus would overlap in a grid card).
- NavigationDrawerModal: panel + scrim are position:absolute, so a `position:relative; overflow:hidden` host contains them. Its container/scrim colours come from the bridge (fixed in the second preview wave).
- Elevation shadows are faint on this dark ground: show levels on a `surface-bright` stage with equal `surface-container-highest` tiles.
- Badges: `Badge` (labs) self-positions against a `position:relative` parent; `ExpressiveBadge` has no positioning — the wrapper places it.
- BrandedFab: never size the slotted mark inline (the FAB sizes it); `size="small"` isn't a branded size. NavigationTab `disabled` has no visual; `hideInactiveLabel` is driven by the bar's `hideInactiveLabels`.
- Selection in Expressive menus renders in tertiary-container (blue) — the theme, not a bug.
- Fixed globally in components/theme-bridge.css during this sync: selected switch icon contrast (theme's on-primary-container is dark), `md-icon` font-variation axes so `--md-icon-fill` works on `<Icon>`.

## Re-sync risks
- `react/src/index.ts` and `react/docs/` are generated from node_modules/@material/web — bumping @material/web changes props/slots; re-run `npm run build` in react/ and re-verify.
- `react/dist/styles.css` is assembled from repo files (fonts/, tokens/, components/*.css): any theme edit needs `cd react && npm run build` before syncing.
- Token kinds: Claude Design warns on custom properties whose kind it can't infer (motion curves/durations, line-heights, opacities, var() aliases). `tools/tag-token-kinds.mjs` tags them in place with `/* @kind … */` inside the value (2026-10-08, 116 tags across tokens/ and components/); `tools/build-components.mjs` re-runs it on m3-system.css after re-copying it from @material/web. A new token of that sort, or a new @material/web token family, needs a rule in its SPEC, then `node tools/tag-token-kinds.mjs` + `cd react && npm run build`. The `--md-sys-typescale-*-axes` family (`normal` / `"ROND" 100`, 30 tokens in m3-system.css) was the first such miss: 30 warnings survived the 2026-10-08 sync until a `font` rule for it landed later that day (styling-only re-upload: `_ds_bundle.css`, `styles.css`, `_ds_sync.json`).
- Full Material Symbols are pinned to one google/material-design-icons commit (tools/fetch-symbols.py COMMIT); bump and re-run to pick up new icons, then rebuild react/. The repo pages' subset (tools/fetch-fonts.py) is separate.
- Besides the synced files, the project holds `templates/m3-web-app/` (a Design-agent template) and Design-agent files at the root (`Canvas.dc.html`, `support.js`, `.thumbnail`). Syncs never touch them.
- First sync (2026-10-05) went into the existing "Material 3 Expressive" project (re-adopted on the user's ask). The CSS-only baseline pages that project held (components/*.html, foundations/, templates/app, tokens/*.css, readme.md, theme.json, thumbnail.html) were deleted with the user's OK — the baseline lives on in the repo under baseline/. The static `templates/material-web-showcase/` page (tools/stage-claude-design.mjs) and the Design agent's `patches/` folder were deleted on 2026-10-08 — every component has a live preview card, and the stale copy only drifted from the theme.
